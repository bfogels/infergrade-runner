# Explicit managed-download cache controls

Models offers Keep, per-download deletion and Clear unkept Runner downloads. Only a newly verified Runner installation recorded with the exact file identity is managed. Earlier/unowned files, partial downloads, symlinks and external model folders are preserved by these controls; a modified/replaced file loses deletion eligibility. The starter download uses the same pinned core resolver and ownership path. There is no automatic eviction in this slice.

Python readers hold shared OS leases before resolving/verifying/preflighting models, through execution and subprocess cleanup. Worker listeners also hold the local default/host cache lease throughout listening, protecting locally queued work. Parsed custom cache roots, file URIs and canonical targets of local aliases are included. Native work leases the default cache; a selected model in a custom managed cache additionally retains its canonical-parent lease inside the actual blocking diagnostic. Cleanup takes a nonblocking exclusive lease plus serialized metadata lock; Keep/last-use metadata uses the same lock order. Native maintenance fences new work admission. Idle offline Runner does not reserve unknown remote jobs; no such protection is claimed. Explicit legacy CLI partial-prune behavior remains available, now fenced against current leased clients. Older executables do not participate in the new lease protocol.

Focused tests cover unowned/external/partial/kept preservation, replacement refusal, real subprocess exclusion and crash release, multiple readers, metadata/path refusal, custom roots/file URI/symlink aliases, download producer ownership, native reader exclusion and native/Python interoperability. Desktop Node68 and Vite build pass. Native57 tests pass with two existing opt-in tests ignored; Clippy passes. Four1060×900/375 light/dark Models captures were inspected. An ephemeral browser native-command adapter verified keyboard Keep, failed-save rollback, disabled kept deletion, successful unkept deletion preserving kept/unowned entries, and visible busy refusal; this is UI QA, not native filesystem proof. The adapter is removed after verification. Windows/Linux package workflows explicitly run the interoperability tests before their install/launch smoke. Full clean core suite and actual platform results remain landing gates.
