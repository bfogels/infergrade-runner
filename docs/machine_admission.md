# Machine benchmark admission

`infergrade admission pause` prevents new claims on this machine. The active benchmark, including download, generation, scoring and upload, continues; queued jobs and ordering remain in Hub. `infergrade admission resume` enables claims again. `infergrade admission status --json` returns only the local schema and boolean preference. This preference is distinct from Stop listener and from individual job pause/cancel.

A separate config sibling admission.json is atomically written with user-only permissions. All job claim paths acquire the same cross-process admission lock as preference writes. The lock is released before execution. A claim already in flight may become current work before pause is confirmed; pause confirmation waits for admission to finish. Claim transport has a 30-second network timeout so a stalled response releases the admission lock. Ambiguous network responses retain the existing Hub lifecycle/recovery semantics; pause does not cancel or rewrite admitted jobs.

The listener stays connected and heartbeats admission_paused in metadata while retaining listening/busy lifecycle semantics. Restart reads persisted state before its first claim. Invalid/oversized/nonregular/linked state blocks new claims. Explicit pause/resume repairs corrupt regular state; linked state is refused. Desktop controls must share INFERGRADE_CONFIG_DIR with the listener and show pending/error state until confirmed. This core change does not yet implement the desktop toggle or Hub paused rendering.

Focused validation: six admission tests include a real stalled HTTP claim, subprocess write serialization/crash recovery, durable restart, active execution after pause, and paused authenticated heartbeat without claims; eight cache tests and 39 worker tests passed after extraction of the shared OS file-lock implementation. Full Runner suite and review receipts are recorded in the PR/root delivery ledger. No native GUI or production acceptance is implied.

Heartbeat follow-up: registration and every idle/error/busy/completion heartbeat include a bounded, nonblocking atomic snapshot of reported admission. Malformed or inaccessible preference projects null and a fixed repair warning, preserving active-job status/current ID and never aborting scoring/upload. Strict future claims still take the admission lock and fail closed. Eight admission tests include active pause followed by corruption with successful upload/completion, held-lock snapshots and subsequent blocked claim; worker39 regressions pass. An actual private loopback listener reported paused while staying connected, without claiming jobs.
